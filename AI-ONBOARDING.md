# AI onboarding for a new installation

Start in the unpacked source folder. Read AGENTS.md, README.md, docs/FIRST-RUN.md and docs/SETUP.md. Confirm package.json name is `annunciator-public`. Work only in this checkout and the user's explicitly chosen computers. Do not import settings, SSH keys, account data or source history from any other installation.

Ask the user for: Linux server computer/account; localhost-only or LAN/VPN access; dashboard name; each host's name, address and probe port; service health and open URLs; desired telemetry; and whether to enable controls or Jev. Confirm which specific target may receive a key or permission change. A host's ability to be monitored does not authorize power commands. If inputs are incomplete, create the localhost starter and explain the missing items.

Run `python3 tools/setup.py` interactively. It creates ignored `server/config.local.json`, own `runtime/setup/` files, and optionally a dedicated SSH identity and Jev configuration. Use `--check server/config.local.json` after edits. The wizard creates *local* setup scripts for target machines; it does not execute them remotely. Ask the user to review and run them on each machine they own. Then verify SSH from the account running the dashboard. Use `python3 tools/doctor.py` for non-destructive checks.

For Jev, the user creates their own OpenRouter API key. Run `python3 tools/jev_key.py` on their server to save it locally with hidden input. Start `runtime/setup/start-memory.sh`, inspect `/health`, then test a harmless sample fact via `tools/doctor.py --jev-test` only after they accept that it sends the text to OpenRouter and may incur a charge. On the same computer as Codex, run `runtime/setup/register-codex.sh`, then `codex mcp list`; restart Codex if already open. Copy the generated `runtime/setup/AGENTS.memory.md` guidance into this project's instructions if the user wants automatic memory routing. For a separate Codex computer, configure a private tunnel and local adapter as described in docs/SETUP.md. Never place keys in prompts, docs or Git.

Jev returns typed routing suggestions. Honor `dont-store`, do not save secrets, review confidence below 0.70, acquire a write lease before editing `runtime/jev/MEMORY.md`, and release it after. Jev does not operate the dashboard, grant permissions or save memory automatically. Router setup is optional for people who only want monitoring.

Start the dashboard with `runtime/setup/start-dashboard.sh`. Verify `/api/health`, `/api/state`, Overview, Systems, details, Log, Setup, Settings and phone-width layout. Check real host/service reachability from the server. Read docs/FEATURES.md for optional prerequisites and honest limits. Controls, wake, Windows telemetry, phone notifications and updates need real-device checks against the user's selected targets. No test should power off a computer merely to prove setup.

Development map: server/annunciator.py and public_config.py; memory/router.py and mcp_stdio.py; tools/setup.py and setup_support.py; web/app.js; Android under android/. Keep the Android ID unique to this source. Run `python3 -m unittest discover -s tests -v`, `python3 tools/audit_public.py`, Python/JS syntax checks and the Android build when changing native assets. Source sharing uses `tools/package_public.py`; inspect its output before publishing.

Prompt a friend can give Codex: “Read AI-ONBOARDING.md and docs/FIRST-RUN.md. Set up this Annunciator source for my own machines. Ask me for missing addresses and permissions. Run the wizard and doctor, explain every generated file, help with the optional Jev/OpenRouter/Codex setup, and verify only systems I choose.”
