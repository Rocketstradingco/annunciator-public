# First run: what the wizard does

**You need:** a Linux server with Python 3.10+, a browser on the same computer, and the source ZIP. Optional remote metrics need SSH on the target. Optional Jev needs an OpenRouter account and API key. Android is optional.

1. Unzip the source ZIP (or `git clone` the repository) and open a terminal in that folder. Run `python3 tools/setup.py`. To look first, `python3 server/annunciator.py` starts a localhost-only demo from `server/config.example.json` at http://127.0.0.1:18160/.
2. Give the dashboard a name. Choose `127.0.0.1` for use on the server only. Choose a reachable LAN address or `0.0.0.0` if phones or other computers should connect; manage firewall access yourself.
3. Add your computers. A name, address and TCP probe port are enough for online/offline status. Supply `user@host` only if you want SSH metrics, containers or power. Add HTTP services with a URL the *server* can reach. Supply separate open URLs a phone/browser can reach.
4. Choose whether to enable controls, a dedicated SSH key and Jev. All are optional. Controls get their own key; they cannot run until a target has its required permissions.
5. The wizard writes `server/config.local.json`, `runtime/setup/setup-report.json`, a foreground starter, and a systemd user unit. These local files contain your own addresses and stay out of sharing archives. It never contacts or changes another host during setup. Use `--force` only when you intend to replace local config.
6. Run `python3 tools/doctor.py`. It validates config and reports TCP/HTTP reachability, SSH, router and service readiness without sending control actions (`--no-probe` skips the reachability checks). Until the dashboard is running, its own host and service entries report CHECK; run the doctor again after starting it. Start `runtime/setup/start-dashboard.sh` and open the reported URL. If you chose LAN listening, use `http://YOUR_SERVER_IP:PORT` on other devices. In Android Settings enter this URL; the APK contains none.

**If you chose SSH:** the wizard creates `runtime/ssh/id_ed25519`, a public key and `runtime/ssh/config` for only your selected targets. Review the generated target scripts in `runtime/setup/targets/`. Run the matching script as the *intended monitoring account* on each selected computer to install the public key. Linux `--power`, `--docker`, and `--wol CONNECTION` options change only the named permissions when explicitly passed. Windows `-EnableSsh` requires an elevated shell and enables OpenSSH on private networks. Verify with `ssh -F runtime/ssh/config monitor-YOUR-ID` from the dashboard computer. The wizard never sends the scripts to remote machines.

**If you chose Jev:** run `python3 tools/jev_key.py` to enter your *own* OpenRouter API key without displaying it. Run `runtime/setup/start-memory.sh` in a second terminal. Its health URL uses loopback and its access key is in `runtime/jev/router.key`. With the memory router healthy, run `runtime/setup/register-codex.sh` on the same Linux computer where Codex runs; it adds `annunciator-memory` only if that name is unused. `codex mcp list` should show it. Codex can route facts and manage cooperative write leases. It cannot edit memory through the router. Copy `runtime/setup/AGENTS.memory.md` into project instructions if desired. A Jev test is `python3 tools/doctor.py --jev-test`: it sends a harmless sample fact to OpenRouter and may incur a small charge. [Jev details](SETUP.md#12-jev-and-codex).

For automatic startup on a Linux desktop/server, review the generated service files, then run `python3 tools/install_services.py`. This enables only the reviewed units generated for this installation. If you want boot startup without login, run `sudo loginctl enable-linger YOUR_USER` yourself. Foreground start remains the simple route.

`server/config.local.json`, `runtime/`, target addresses, generated keys, Jev decisions and APK signing material must stay private. They are ignored and excluded from `tools/package_public.py`. The source ZIP is the shareable artifact.
